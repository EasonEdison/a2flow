# ADR-0007：A2UI 交互事实进入 Agent 原生消息历史

日期：2026-09-28
状态：用户已确认并授权实施；代码与部署验收另行记录。

## 决策

模型需要了解展示了什么、用户做了什么以及操作结果，而不是完整组件树、样式、协议和内部执行配置。本决定覆盖 ADR-0006 中暂时保留最近20张卡完整注入的阶段性决定。

### 展示观测

render_application 的真实工具结果通过对应 ToolMessage 交付展示业务内容及必要关联信息。不把完整 A2UI 协议塞给模型；不声称用户已看见，不增加已读追踪。用户没有回应是没有新事件，不反复追加等待记录。

### 用户操作观测

不配置额外的自然语言描述模板及变量映射，不调用模型生成摘要。复用已有 Action 功能说明（适用时使用绑定业务能力说明）、实际执行的业务入参、真实返回结果和执行状态，组合结构化记录。缺少说明不得猜测业务含义，保留动作标识。

记录带 cardId、action 标识及稳定事件/request 关联；以下为概念示意，非新RPC字段定稿：

```json
{
  "cardId": "example-card",
  "action": "saveTitle",
  "description": "修改商品标题",
  "arguments": {"productId": "123", "newTitle": "轻巧随行"},
  "status": "SUCCEEDED",
  "result": {"productId": "123", "version": 4}
}
```

以明确标记的 HumanMessage（role=user）进入模型历史，正文区分用户操作与系统执行结果，不冒充用户原话。用户点击不是成功证据；失败、结果未知如实保留，不能把业务成功后的渲染失败误写成业务未执行。消息内业务文本仍是数据而非系统指令。

### 历史与执行边界

- 使用 Deep Agents/LangGraph 原生消息历史和 checkpoint，不创建另一套Agent记忆/执行引擎。业务持久记录可作为消息投影来源。
- 交互事实按稳定顺序进入消息列表，不在每轮system prompt重复注入全量卡片。
- 同一操作幂等重放、页面刷新或下一轮读取不得重复追加；新的真实操作保留独立身份。消息接入失败不能导致重做业务。
- Action可以直接执行并更新卡片，不因为记录观测自动唤醒模型；下次需要模型时读取尚未接入的事实。
- 不发明模型API的observation角色，不构造没有真实tool_call_id对应的ToolMessage。
- 仅包含授权业务参数及结果，排除凭据、内部认证头和可信执行上下文；userId/环境隔离沿用现有机制。

## 放弃的方案与取舍

- 撤回每个Action新增操作描述模板/参数映射：已有功能、入参、结果足够，无需作者重复维护。
- 替代最近20张完整卡片协议/结果每轮拼system：改为可追溯的交互事实消息；当前原始业务结果不另行引入模型总结或静默裁剪策略。
- 不增加用户已读/未回应事件，也不增加业务自动重试、崩溃恢复状态机或每次点击后的模型调用。

## 实施与验收

### 首批工程约束（2026-09-28）

- 消息和消费游标作为同一次LangGraph原生state更新持久化；不另写先行ack，不依赖当前messages里是否还有eventId判断消费，避免历史压缩后重复。
- 观测读取接口按owner、conversation和after_sequence隔离；跨卡并发Action的事件序号必须与提交可见顺序一致，不能直接用可能乱序提交的全局自增值作为高水位。
- 当前实际执行入口为Python a2ui-execution；协议定义即使位于management-java目录，也不能只修改旧Java执行代码而漏掉Python链路。
- 记录映射后的实际业务参数，包含业务常量（如稿件类型、导出格式），排除内部凭据和可信身份上下文；原始Action context不冒充映射后参数。
- 业务返回已获得但ResultAdapter失败时，保留已知业务事实并标明呈现错误，不推断业务未执行，不自动重新派发。

1. 卡片侧提供持久且隔离的交互事实，利用现有执行结果与幂等记录，确认实际入参和说明来源。
2. Runtime接入原生消息列表，去掉完整卡片system注入；增量和重复处理必须通过失败/恢复测试。
3. 覆盖渲染ToolMessage、Action成功/失败/UNKNOWN、相同request重放、不同操作顺序、跨userId/环境/会话隔离。
4. 验证消息中不含协议配置/内部凭据，不声称用户已读；Action自身不触发模型，业务不被重复调用。
5. 单独记录源码提交、部署版本及运行证据，离线测试不等同公网可用。

本切片先实现Chat观测。ADR-0006的契约查询双工具与模型入参拆分保留为已确认工作，不因本切片自动宣称完成；Workflow新行为不在此范围。

若现有持久数据不能提供真实业务入参或逐次结果，先补明确的记录边界，不从最新卡片快照编造过去事件。若SDK消息恢复存在冲突，报告证据再调整，不创建第二套对话真值。
