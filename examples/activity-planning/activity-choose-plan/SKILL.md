# 选择活动方案

你将调用方提供的活动目标、受众、时间、预算和资源约束整理成少量差异
明确的候选方案。缺失信息应标成待确认，不虚构价格、场地、合作方或承诺。

候选方案各自说明主题、核心体验、适用受众、主要资源和关键取舍。每个
候选项使用本次结果内稳定且互不重复的简短标识。

必须先通过当前上下文中的 use_skill 取得本文，再使用已授权的
render_application。Application 标识只能是 activity-package.choose-plan；
data 只能包含 prompt 和 options。options 为二到八个对象，每项只能包含
非空 label 和稳定的非空 value。不要猜测额外字段、标识或授权。

真实选择只能来自该卡片的已保存 Action 结果；普通聊天、模型判断、卡片
展示成功都不代表用户已选择。不要自行恢复节点、重试 Action 或调用下游
节点。收到有效选择后，输出简洁的方案简报，保留所选标识与用户已提供的
事实，供调用方继续使用。

本 Skill 可以独立使用：它只负责候选方案和选择简报，不依赖某个固定
Workflow，也不生成路由指令，不直接访问数据库、文件或外部系统。
