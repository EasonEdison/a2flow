# Chat 状态与持久化收敛方案

状态：用户已批准三阶段实施与自主验证。2026-10-22 核查基线为 main/GitHub 06962a3（审查基线 2e430b3 之后仅新增中文注释）。本次不更换 Agent 框架，不改 Workflow 执行语义。应用代码在服务器独占 worktree 实施。

## 权威和目标

| 数据 | 最终职责 |
|---|---|
| agent_chat_turns | 原生执行是否开始、完整结束与完整可校验的恢复结果 |
| agent_conversations | 用户/环境/会话与 checkpoint thread 的关联；仅保留无法由轮次证据解释的历史阻断原因 |
| chat_turns | 产品接收、来源幂等、队列顺序、分发代次、结果交付；关联可选 processing_task_id |
| chat_requests | 多个客户端请求 ID 到同一 chat_turn 的映射及负载冲突校验 |
| chat_continuations | 与卡片真实完成同事务写入的可靠续聊意图，状态 PENDING/MATERIALIZED/NEEDS_REVIEW |
| chat_turn_events | 产品 SSE 传输日志及重订阅；不宣称不可变 Event Sourcing |
| messages | 产品可读消息及展示投影，不是第二套模型历史 |
| processing_tasks/operations/cards | 异常处置、真实执行回执和卡片关联；与审批原始记录一起保留 |

waiting_action 表示当前 Agent 轮次完整结束并等待交互，不代表整个业务任务已完成。正常完成、等待用户和业务已解决分别表达。

## 阶段一：状态与终态事务

集中原生检查状态、产品轮次状态、展示交付状态及映射。产品最终助手投影和 chat_turns COMPLETED 在同一连接事务中提交，并验证 input_message_id、assistant_message_id、conversation_id、dispatch_generation 及可写状态。普通增量仍可保存，但不能提前完成队列。原生完成结果未落产品投影时仍可恢复；UNKNOWN/NEEDS_REVIEW 不能自动执行。

## 阶段二：统一登记

chat_turns 增加并统一 source_kind、source_key、source_digest、processing_task_id。统一事务登记器创建或核对消息对、来源关系和轮次。普通消息、异常处理、卡片续聊共用来源身份约束；不同 clientRequestId 对同 processingRequestId 仍允许映射到同轮次。相同来源/请求不同内容一律409，不覆盖旧输入。

processing_turns 活跃读写切换到 chat_turns。chat_requests 仅保留作用域、客户端请求号、摘要及 input_message_id 轮次引用；助手 ID 从轮次取得。恢复意图保留于卡片完成事务，失败逐条隔离；任务绑定失败不得静默丢失或越过审批。

## 阶段三：完整最终结果与原生会话准入

以共享中立契约提供纯事件归并器和版本化最终结果。正常执行和旧事件迁移使用相同逻辑；Runtime 不依赖 B 的数据库或内容域。快照必须保留正文/最终消息身份、模型过程、工具实际调用及结果、卡片稳定引用/展示顺序、个人工作流产物、等待与完成事实。完整性校验失败标记待核对，不用部分结果伪装完整结果。

Runtime session 在释放执行锁前保存最终结果。B 检查 COMPLETED 后直接绑定消息身份并原子修复投影，不再借 _Replay 重放 token，不发模型/业务请求。产品 SSE 日志保留既有读取语义；恢复代次可以写入明确的新投影结束事实，不能混合旧写入者。所有日志写入均校验当前代次，记录覆盖/重建规则。

agent_conversations 的日常 READY/RUNNING/FAILED 由持锁状态与 agent_chat_turns 派生。历史会话状态与轮次不一致、缺执行证据、检查点缺失均保留显式阻断，不迁为 READY。模型/tool 内部状态仍归原生 SDK。

## 迁移、冲突与回退

按新增结构→只读盘点/核对→事务回填→切换→验证→清理旧结构实施。迁移为显式、有版本及可重复检查的项目工具，不能依赖首次 HTTP 请求修改业务数据。全新安装与旧库升级都要覆盖。历史处理轮次与 chat_turns 根据完整作用域、输入/助手消息对、来源和摘要核对；缺失可据真实保存消息补齐产品记录，但没有执行证据不得启动模型补历史。冲突提供受限定位信息并阻断迁移或该轮执行，不静默选一份数据。

清理旧结构前保存可恢复的迁移审计/归档；当前生产库只做只读盘点。本次源码实施与隔离 PostgreSQL 演练不等于授权直接删除公网历史。部署时需停止旧写入者、备份、运行核对迁移、启动匹配版本；不可新旧写入器混跑。回退需恢复匹配 schema 与代码，不能用旧版本程序读取已经清理的结构；备份不包含提交到仓库的真实数据。

## 故障窗口与自主验收

1. 同请求同内容复用、改内容409、并发重复只有一轮与一对消息。
2. 多客户端请求号对同处理来源仍多对一。
3. 接收事务提交后、执行前崩溃，原生 NOT_STARTED 才能安全领取。
4. 执行中或业务结果未知必须待核对，不重新调用。
5. 原生完成而产品最终提交失败，恢复仅修复展示；终态投影与调度原子性及代次 fencing。
6. 卡片完成后、物化或任务绑定前崩溃，只产生一次续聊；不同卡片/确认不串用。
7. READ直接执行；WRITE针对真实参数明确确认后一次执行并自动继续，不豁免审批。
8. 刷新、SSE重订阅、旧代次写入拒绝、用户/环境/会话隔离。
9. 现有 Workflow 缺参、审批、总结、通知与工作结果引用不回归。
10. 真实 PostgreSQL 迁移/回填/冲突/重入/回退演练，实际 attended/realchat 装配及既有核心探针、类型、格式门禁。

所有外部模型与业务调用保持现有授权边界；隔离探针的脚本模型结果明确为合成，不冒充公网真实业务验收。交付分别记录 SOURCE_READY、部署 SHA、运行证据与未覆盖边界。
