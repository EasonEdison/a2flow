# Chat write confirmation

Read-only capabilities run without an additional prompt. WRITE/DESTRUCTIVE with REQUEST_APPROVAL use a host-authored temporary card showing the actual arguments. The model cannot supply approval receipts. A durable same-owner claim precedes RPC; immutable source, action, arguments and tool scope bind the receipt. A completed confirmation resumes the conversation using the actual ACTION outcome, without repeating the write.

Handling tasks retain their original task, turn and tool-call identity. WAITING_INPUT admits only its exact claimed confirmation card and no other waiting card. Ordinary temporary input never grants this exception. Unknown outcomes remain terminal and are not retried.

The shared helper and RPC governance contract are delivered by the parent execution-guards change. This change owns Chat adapters, card transitions, and handling-task admission. Existing A2UI mapped actions use the same explicit confirmation principle. PrepareAct performs all card/action/mapping checks without executing business transport and returns the actual capability arguments and governance. WRITE converts the original card to a host confirmation while preserving its card ID and Workflow identity; its frozen original display, private metadata, action and input live in an owner-scoped immutable preflight request record. Confirmation claims a second request and Act revalidates the frozen parameters with a typed receipt. Successful result projection restores the original Java-RPC display and uses the existing Workflow completion observer. A new save on a reusable card receives a distinct confirmation identity; retries of the same confirmation never dispatch again.

Preparation is not a business result and does not complete a Workflow node. Ordinary temporary submission cannot bypass A2UI confirmation dispatch. Result-unknown and presentation-failure paths preserve the existing non-retry semantics. The actual Python execution host and canonical proto are delivered by the parent and architecture changes; the Java implementation alone is not deployment evidence.
