# A2UI write confirmation compatibility

The deployed joint execution host is Python `a2flow_a2ui.host`, not the retained Java facade. This addition belongs to that actual host.

`PrepareAct(ActRequest)` reuses current publication, generated-origin, owner, card surface, action schema and mapping checks, then compiles and validates the mapped capability request without business transport. Its response contains the current immutable capability contract, frozen sorted UTF-8 JSON arguments and binding ID. It does not load data, consume a receipt or modify a card.

The trusted Runtime saves a confirmation on the original card. On the second explicit confirmation, it calls `Act` with a typed host-only receipt. `Act` repeats publication and mapping checks, then the shared capability executor verifies the source and exact mapped-argument digest before durable consumption and RPC. A model cannot put the receipt in action context. READ keeps ordinary Act behavior; LOAD never receives a receipt and cannot authorize a write.

Dynamic trusted-time mappings can differ between preflight and confirmed Act and are then rejected. This deliberately preserves argument integrity; it does not silently freeze/override newly computed trusted context. No generic retry or exactly-once business claim is added.

Protocol additions: ActRequest.approval_receipt field 9; PreparedAction fields capability=1, arguments_json=2, binding_id=3; PrepareAct RPC. Python generated stubs are regenerated by the integrating thread. Existing field numbers and reserved fields remain unchanged.
