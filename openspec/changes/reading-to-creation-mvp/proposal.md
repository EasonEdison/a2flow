# 阅读到创作助手：首版业务场景提案

日期：2026-09-23。状态：用户已确认，内容业务服务改为 Python，仅 M 端使用 Java；本次只记录方案和数据库设计，不创建实际表、不导入资产、不部署服务。

## 1. 要解决的问题

A2Flow 已有平台基础，但需要真实业务闭环验证 Skill、业务能力、A2UI 和 Workflow 是否真正可组合。首个场景选择知识型自媒体创作：用户提供阅读资料，理解资料、确定表达角度，最后得到自己确认的内容稿。

核心交付不是一段聊天回答，而是可重新打开的创作项目，包含原始素材、已确认观点、选题和最终稿件。生成内容标注依据；原文事实、作者观点与模型建议分开，不能编造引文。

## 2. 首版体验

示例：用户粘贴自己有权使用的读书笔记，输入“面向职场新人，写一篇关于注意力管理的分享”。

| 阶段 | Skill 做什么 | A2UI 展示与操作 | 保存结果 |
| --- | --- | --- | --- |
| 阅读理解 | 提炼主要观点、对应原文依据、疑问和可用素材 | 展示观点与出处；勾选要使用的观点，补充个人理解，点击确认 | 阅读简报及用户确认的素材 |
| 选题策划 | 根据已选素材、受众和目标提出少量不同选题 | 选择一个选题，可修改标题和表达角度，点击确认 | 选题单 |
| 内容成稿 | 按选题生成正文或口播稿，区分事实和建议 | Markdown 预览，编辑内容，保存草稿、确认定稿、下载 | 有版本记录的稿件及导出内容 |

三个节点顺序执行，每个都有实际 A2UI 交互。Workflow 外框、节点进度和运行控制仍是产品原生页面，不用 A2UI 拼整个工作流。

三个 Skill 也能单独在 Chat 中使用。例如已有选题时直接请求写作，不强制先运行前两个 Skill。缺少必要业务信息时在当前 Skill 中补齐，不把它写成固定内部业务子图。

## 3. 首版范围与建议默认值

- 输入：粘贴文本，填写标题和可选来源链接；链接仅记录出处，不自动抓取网页。建议先限制单份素材 30,000 个字符，超限明确提示，不静默截断。
- 输出：图文正文、口播脚本二选一；首版都是文字产物，不生成视频。允许 Markdown / TXT 下载。
- 单个创作项目首版关联一份素材；多资料对照、整本书上传和知识库问答后续再做。
- 普通用户管理自己的创作项目并调用已发布资产；只有管理员维护 Skill、能力、Application 和组件。
- 先完成三个 Skill 的独立 Chat 链路，再组合成三节点 Workflow；不扩展新的分支、并行和重试语义。
- 原始输入、业务产物保存在 PostgreSQL；不新增对象存储，不另外维护一套聊天记录或记忆。

以上首版范围已由用户确认，尚未实现；具体限制仍需通过实现与验收验证。

## 4. 不在首版内

公众号/小红书自动采集、第三方账号绑定、视频剪辑、语音合成、自动发布、定时发布、互动数据分析、向量知识库，以及 M 端 AI 辅助编排。

这些将来由业务服务的外部适配器接入。平台接口是否开放、账号授权及使用条件必须接入前单独核实；不以绕过访问限制为方案前提。

## 5. 已确认的三个选择

1. 首版做“粘贴资料 + 可选出处链接”，暂不支持文件导入和抓取。
2. 保留图文正文与口播脚本两个文字输出选项，共用写作 Skill。
3. 最后一步只定稿、保存、下载，不发往任何外部账号；后续选定具体平台再接发布。

实现细节见 [design.md](design.md)，任务与验收见 [tasks.md](tasks.md)。
