# Evidenced anomaly follow-up in Chat

Approved scope: scheduled workflow attention -> explicit Chat handling request -> temporary missing-input form -> authorized existing business operation -> saved result linked to the original attention. Original runs and read acknowledgement remain independent.

An explicit processing target creates an owner/environment/conversation-bound task. Ordinary run references remain read-only context. A task survives temporary form continuation using a durable card binding, never the latest unrelated message. The model cannot mark work resolved. Returned RPC results are recorded as execution receipts, not proof that the business anomaly is solved. An explicit human conclusion is recorded separately.

Implementation uses existing business capabilities; no new business backend or automatic remediation. The acceptance scenario saves a review-record draft through existing content project/source/artifact capabilities. All test data is fictional and the triggering rule is supplied only for that demonstration.
